# 多轮问询手册（每次开工前读一遍）

这个 skill 最容易犯的错不是 API 调错，是**替用户做了决定**。
生成花钱、剪辑改交付物、字幕配乐改观感，这些都必须用户点头。本文件规定怎么问。

---

## 一句话原则

> **默认什么也不做，用户明确说了才做；说得不明确，就再问一次。**

沉默、含糊、「随便」、「你看着办」、「按最佳实践」统统不算同意。
遇到这些回答，回到最保守方案（只给片段、零后期），复述一遍再确认一次；还是含糊就停下来，把已确认的信息整理给用户，请他明示。

---

## 决策树

```
用户说要做视频
   │
   ├─ 第 1 轮：需求（讲什么/发在哪/多长/什么风格/参考片）
   │     → 复述理解，等确认
   │
   ├─ 第 2 轮：分镜表（每镜画面+时长+顺序+总时长+比例）
   │     → 改到用户说 OK
   │
   ├─ 第 3 轮：★「要我帮你剪辑合成吗？还是只要片段？」
   │     ├─ 只要片段 ────────────────┐
   │     ├─ 要剪辑 → 第 4 轮逐项问 ─┤
   │     └─ 含糊 → 再问一次，不推进  │
   │                                 │
   └─ 第 5 轮：estimate + 确认单 ←────┘
         → 「按这个开始生成，确认吗？」
         → 明确肯定 → 才动手

动手时：
  剪辑=否 → run → clips → present_files 逐个交付（永不调 assemble）
  剪辑=是 → run → assemble [只带用户确认过的参数]
```

## 五轮逐轮话术

### 第 1 轮 · 理解需求

用 `AskUserQuestion`，一次 2–4 个问题。可推断的不要问，但要复述推断。

示例：

```
questions:
  - "这条片子主要讲什么、给谁看？"        # 题材/受众
  - "大概多长？"                          # 15s / 30s / 60s
  - "想要什么调性？"                      # 温暖 / 冷峻 / 活泼 / 高级
  - "发在哪个平台？"                      # 决定比例
```

收尾复述：

> 「我理解的是：给 30 秒竖屏短视频，介绍这家咖啡店的氛围，温暖治愈、自然光、胶片感，发抖音。比例我按 9:16、分辨率 1080p 来，对吗？」

⚠️ 别一次问十个；别把第 3/4 轮的问题混进来。

### 第 2 轮 · 确认分镜

把 `storyboard.json` 翻译成人话贴出来：

```
1. 晨光洒进店内，拿铁冒热气，镜头缓推        5s
2. 手冲壶注水特写，咖啡粉膨胀               5s
3. 靠窗年轻人翻书，暖黄吊灯，镜头横移       5s
4. 心形拉花微距收尾                        5s
共 4 镜 / 20s / 9:16 竖屏
```

问：「顺序和内容要改吗？有没有必须出现 / 绝对不能出现的东西？」
用户改 → 改分镜 → 再贴一次 → 直到 OK。

**同一轮里顺带确认「加速环节」**（详细做法见 `references/pipeline.md`）。
这些都会多花钱或改分镜，所以宁可问细一点：

```
「为了让成片更稳，可以额外做几步，但都会多花点生成费用，你要哪些？
  · 先出静帧/角色设定表，把长相和构图定好
  · 先用便宜草稿拼个粗剪看节奏
  · 每个镜头多生成两三版让你挑
  · 边生成边把上一镜末帧接到下一镜，衔接更自然（需要 ffmpeg）
 不做也完全可以，我就按最朴素的方式一次生成。」
```

**默认全不做。** 用户只挑了其中一两项，就只做那几项，别自作主张补全。
有同一个人物或产品时可以推荐做静帧和制作圣经，但推荐不等于替他决定。

### 第 3 轮 · 要不要剪辑（关键，单独一轮）

**必须独立成一轮**，不能和第 4 轮合并。原话建议：

```
question: "生成完这几个片段后，需要我帮你剪辑合成一条完整视频吗？还是只要这几个片段就行？"
header: "是否剪辑"
options:
  - label: "只要片段"
    description: "逐个交付 mp4，不合成、不加字幕配乐，你自己后期"
  - label: "帮我剪成一条"
    description: "接下来我会逐项问字幕、配乐、片头等，确认后才动手"
```

分支处理：

| 回答 | 动作 |
|---|---|
| 只要片段 | `brief.md` 记 `剪辑=否`，**跳过第 4 轮**直接进第 5 轮；此后禁止调用 `assemble` |
| 帮我剪 | 进第 4 轮 |
| 「都行」「随便」「你决定」 | 回：「那我按最保守的来——只给片段、什么都不加，可以吗？」等明确答复 |
| 没答 / 答非所问 | 换个说法再问一次，不推进 |

### 第 4 轮 · 逐项问后期（仅当要剪辑）

**不能打包成「要不要加字幕配乐呀」**，因为用户可能要字幕但不要音乐。建议分两次问，每次 3 个左右：

```
第一轮（声音相关）：
  - 字幕：要不要？文案你给还是我拟？
  - 配乐：要不要？有自己的音乐文件吗？（没有就不加，我不会自己找）
  - 配音/旁白：要不要？男声女声、语速？
  - 模型原生音效：片段要不要自带 AI 生成的声音？（默认无声，
    这是生成阶段的选项，和「后期配乐」不是一回事，别混着问）
第二轮（画面相关）：
  - 片头：要不要？写什么字？
  - 转场：硬切还是淡入淡出？
  - 首尾淡入淡出：要不要？
```

每条纪律：

- **不要替用户选 BGM**。没文件就请他给路径，或明确问「那就不加音乐了可以吗」。
- **不要从分镜模板里继承默认文案**。模板里的 `voiceover`/`subtitle` 是示例，用户没确认过就是没有。
- 用户漏答的项，在第 5 轮的确认单里**点名补问一次**。
- 用户说「先不要，后面再说」→ 记 `否`，交付时提醒他随时可以补做（片段还在，不用重新生成）。

### 第 5 轮 · 汇总 + 成本确认

```bash
python3 scripts/vs.py estimate                        # 只要片段、朴素定稿
python3 scripts/vs.py estimate --takes 3 --draft      # 选了 3 候选 + 草稿 → 按 ×3.5 报账
python3 scripts/vs.py plan --takes 3 --draft --chain # 确认单同步显示倍数与加速环节
python3 scripts/vs.py plan --assemble                # 要剪辑 + 已确认的后期参数
```

**第 2 轮选了加速环节，第 5 轮却按 1 倍报价 = 误导用户花钱。** 倍数必须贯穿 estimate 和 plan。

把确认单和成本一起贴给用户，逐条对：

```
按下面这个来就开始生成了，确认吗？
· 4 个片段 / 20s / 9:16 / 1080p
· 交付形态：只要片段，不剪辑          ← 或「剪成一条」
· 字幕：不做   配乐：不做   片头：不做   转场：无
· 加速环节：静帧/草稿/多候选/尾帧链 都不做   ← 若用户选了，逐项列出来
· 预估成本：约 ¥5.2（即梦档；每加一轮草稿或多候选要重新报账）
· 预计耗时：约 8 分钟
```

**必须得到明确肯定**（「确认」「开始吧」「OK」）才提交任务。
「嗯」「👌」这类含糊回应，再确认一句「那我提交了？」也不为过——马上要花钱了。

## 记到 brief.md

每轮结论立刻写进项目根目录 `brief.md`（模板见 `assets/project-template/brief.md`）。
中途改需求、隔天接着做、换模型，都靠这份记录，不要凭记忆。

最简格式：

```markdown
## 确认记录
| 轮次 | 问题 | 用户回答 | 时间 |
|---|---|---|---|
| 1 | 需求 | 30s 竖屏、咖啡店氛围、温暖治愈、发抖音 | 18:22 |
| 2 | 分镜 | 4 镜 20s，用户说 OK | 18:25 |
| 2b | 加速环节 | 静帧/草稿/多候选/尾帧链 都不做 | 18:25 |
| 3 | 是否剪辑 | **只要片段** | 18:26 |
| 4 | — 跳过 — | | |
| 5 | 成本确认 | ¥5.2，用户说「开始吧」 | 18:27 |

## 后期授权（逐项）
- [ ] 剪辑合成    → 否
- [ ] 字幕        → 否
- [ ] 配乐        → 否
- [ ] 配音        → 否
- [ ] 模型原生音效 → 否
- [ ] 片头        → 否
- [ ] 转场        → 否（硬切）
- [ ] 淡入淡出    → 否
```

**只有打勾的项才能带进 `assemble` 参数。**

## 交付时的自检

- [ ] 用户答「只要片段」→ 目录里**没有** `output/*.mp4`，交付的是 `videos/*.mp4`
- [ ] 用户没确认字幕 → 成片里没有字幕（直接看成片画面；`assemble` 的「本次后期动作」日志应显示纯拼接）
- [ ] 用户没确认配乐 → 没有混入音乐
- [ ] 用的是用户提供的 BGM 文件，不是自己找的
- [ ] `brief.md` 里每一项都有明确回答，没有空白当默认
- [ ] 成本确认过才提交的生成任务

代码侧已经兜底：`assemble` 默认纯拼接，`storyboard.json` 的 `bgm`/`transition`/字幕字段**默认不生效**，
只有 `--use-storyboard`（用户看过确认单后）才会沿用。但**代码兜底不能替代询问**。

## 反例（这些都被判为违规）

1. 用户说「做个 30 秒视频」→ 直接 `run` 完 `assemble --title ... --fade`，还自动烧了字幕。
2. 用户说「不用剪了」→ 还是生成了一个 `final.mp4`「方便你预览」。
3. 用户说「加点氛围」→ 自己找了首 BGM 铺上。
4. 把五轮问题塞进一次 `AskUserQuestion`（一次最多 4 问，塞不下还硬塞）。
5. 用户回「随便」→ 当成「按默认配置全开」。
6. 看到分镜里留着 `bgm` / `subtitle` / `transition` 字段 → 以为用户要配乐、要字幕、要转场。
7. 没跑 `estimate`、没问「确认吗」就提交生成。
8. 中途用户说「还是别加字幕了」，但成片已经烧好字幕就照交不误。
9. 没问就跑 `run --stage draft` 或 `run --takes 3`，自作主张多烧了三倍的钱。
10. 没问就 `chain --apply`，把用户自己选的首帧图覆盖掉了。
11. 没问就跑 `voice` / `media` / `edit` / `export` / `sheet` / `cover`，自己生成配音、素材、改片或多平台版本。
12. 没问就 `run --fallback`（失败会新开任务、可能换风格）或 `run --parallel`（一次提交整批，中断成本更高）。
13. 把「网关支持 Sora / Gemini Omni」说成已验证可用 —— 这些只验过端点结构，没跑过付费实单。
11. 拿「行业最佳实践就是这么做」当理由，替用户决定做哪些环节。
12. 定稿全部生成完才 `chain --apply`，又不重跑后续镜头 → 衔接根本没生效。
13. 用户选了 `--takes 3`，第 5 轮却只贴 1 倍的成本让他确认。

## 用户中途改主意

立刻更新 `brief.md` 和 `storyboard.json`。
**片段不用重跑**（`vs.py run` 幂等，不会重复扣费），只需按新授权重做 `assemble`，或改回只交付片段。
已生成但不符合新要求的成片不要交付，说明一声删掉重来即可。
