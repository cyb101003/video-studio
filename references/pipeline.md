# 生产管线：从一句话到能交付的片子

> 本文件讲「确认之后怎么把活做对」。**开工前的五轮询问见 `intake.md`**，那一步不能跳。
> 本文件里所有会多花钱、会改分镜的动作，同样要先得到用户明确同意（见最后一节）。

---

## 为什么需要一条管线

AI 视频最容易翻车的不是 API 调错，而是这几件事，检索到的从业者资料高度一致：

| 常见翻车 | 后果 | 对策 |
|---|---|---|
| 每镜独立生成 | 角色换脸、服装变色、光线跳 | 身份块逐字复用 + 锁定参考图 |
| 中途换模型 / 模型版本 | 风格直接断，观众一眼看出是拼的 | 全项目锁同一个 provider + model |
| 直接生成视频再改 | 静帧改几秒，视频重跑几分钟，钱白烧 | 先静帧、再草稿 animatic、最后定稿 |
| 只生成一版就用 | Motion 模型不可预测，第一版常常不能用 | 每镜 3–5 候选，横向挑 |
| 相邻镜头各画各的 | 切口处气质突变 | 上一镜末帧接下一镜首帧 |
| 没存 prompt / seed / 参考图 | 想重拍只能从零开始 | 每次生成都落盘 `.vs/jobs.json` |

> 关于「哪個模型一致性最好」：截至 2026 年没有 Tier 1/2 级公开基准，流传的排名都是从业者共识，
> 不要当权威结论写给用户。有一条从业者自测数据可参考（PixMind，30 镜）：
> 纯文字 prompt 有 9/30 镜保持住角色，锁定参考图 + 身份块有 24/30 镜保持住。
> 这说明**方法比选型更重要**，也说明为什么本 skill 把「锁定」做成默认行为。

## 阶段 0–7 总览

| 阶段 | 做什么 | 交付物 | 主要命令 |
|---|---|---|---|
| 0 · 需求 | 多轮询问、成本确认（按倍数报账） | `brief.md` | `vs.py plan` / `estimate` |
| 1 · 制作圣经 | 身份块、风格、光线、参考图、模型、seed | `bible.json` + `refs/` | `vs.py bible` |
| 2 · 镜头表 | 每镜六要素 + 顺序 + 时长 | `storyboard.json` | `init` + Write |
| 3 · 静帧预演 | 每镜先出静帧，把构图/服装/光线改对 | `images/*.png` | ImageGen（Agent 调用） |
| 4 · 草稿 animatic | 720p 便宜草稿拼成粗剪，检查节奏 | `.vs/work/animatic.mp4`（内部预演，不进 `output/`） | `run --stage draft` / `animatic` |
| 5 · 定稿 + 候选 + 衔接 | 每镜 3 版挑一版；**尾帧链在生成下一镜之前做** | `videos/` + `.vs/takes.json` | `run --takes 3` / `run --chain` / `takes` / `pick` |
| 6 · 质检 | 逐镜 QC、统一调色 | 合格片段 | `qc` |
| 7 · 后期交付 | **只做用户授权过的项** | 成片或片段 | `clips` / `assemble` |

> **最容易踩的顺序坑**：尾帧链改的是分镜的 `image` 字段，不会改已经生成好的视频。
> 它不是「定稿之后再补一刀」的环节，而是**生成顺序的约束**。放错位置的代价是：要么白做，
> 要么得把后续镜头整批 `--force` 重跑一遍、再花一次钱。正确姿势见下面「尾帧链接」。

新手项目、纯风景/抽象画面可以跳过 3–6 的大部分（见「什么时候可以简化」）。
**只要片子里有同一个人物或同一个产品，1/3/5 三步几乎是必须的。**

## 一致性三板斧

### 1. 身份块逐字复用

`bible.json` 的 `identity` 是「角色主文档」：脸部特征、发型、服装（颜色/剪裁/材质分开写）、
配饰、体态。写一次，`run` 会把它**原样拼到每个镜头 prompt 最前面**：

```bash
vs.py bible --set identity='28岁女性，齐肩深棕发，右眼下方一颗痣，深绿色高领针织衫，米色长裤，身形偏瘦，略微含胸' \
            --set lighting='侧逆光，光源在画面左侧' \
            --set style='温暖治愈，浅景深，胶片颗粒' \
            --set negative='文字, 水印, 畸形手指' \
            --set seed=12345 --lock
```

生成的 prompt 长这样（只有最后一句在变）：

```
28岁女性，齐肩深棕发，右眼下方一颗痣，深绿色高领针织衫，米色长裤……。统一风格：温暖治愈……。光线：侧逆光……。她推开店门，镜头缓慢前推。
28岁女性，齐肩深棕发，右眼下方一颗痣，深绿色高领针织衫，米色长裤……。统一风格：温暖治愈……。光线：侧逆光……。她低头看书，镜头横移。
```

**纪律**：不要改写、不要换同义词。「深绿色高领针织衫」和「墨绿毛衣」在模型眼里是两个输入。
服装拆成颜色+剪裁+材质写，选一个辨识度高的锚点；配饰单独管理，别混进身份块。

`references` 字段是**资产库清单**（角色正面/侧面/半身/全身、场景不同时段、关键道具）。
`vs.py bible` 会检查这些文件是否存在；要作为多图参考传给模型，需 provider 支持并加 `--use-refs`。
（目前七家里只有 Vidu 声明了 ref 能力，其余主要靠首帧图 + 身份块。）

### 2. 全项目锁同一个模型

**这是原本最容易踩的坑**：`run` 逐镜调用 `auto` 选模型时，
如果某镜有首帧图（i2v）、另一镜没有（t2v），能力匹配结果可能不同，就会换一家 —— 风格必断。

现在 `vs.py run` 整批只解析一次 provider，并把结果写进 `.vs/model-lock.json`，
后续所有镜头、后续所有 `run --only ...` 都沿用同一家。显式传别的 `--provider` 会被拦下并提示；
真要换用 `--unlock-model`（换之前先跟用户说清楚后果）。

`bible.json` 里若 `--set provider=ark --lock`，则连 `--unlock-model` 也要先改圣经，锁得更死。

**纪律**：一个项目一个模型版本，主力 + 备份最多两家，别每镜换。

### 3. 尾帧链接（**顺序比命令更重要**）

把第 N 段的最后一帧作为第 N+1 段图生视频的首帧，头发、服装、姿态、光线、道具状态天然延续。
但**首帧必须在下一镜提交之前就位**，所以正确做法是在生成过程中衔接：

```bash
# ✅ 推荐：从头生成时一次完成，不用重跑、不额外花钱
vs.py run --chain        # 每生成完一镜 → 抽末帧 → 写入下一镜 image → 再生成下一镜

# 补救：项目已经全部生成完了
vs.py chain              # 先预览计划，不改任何文件
vs.py chain --apply      # 改写下一镜 image；命令会列出需要重跑的镜头
vs.py run --only s2,s3 --force   # ← 必须做，否则视频根本没变（会再花一次钱）
```

**`chain --apply` 只改 `storyboard.json` 的 `image` 字段，不会改已生成的 mp4。**
如果把它排在定稿之后又不重跑，衔接等于完全没生效。这是本管线最容易白忙一场的地方。

注意：
- 两种方式都需要 ffmpeg（抽帧用）；没装就只生成片段，衔接这一步跳过
- `chain --apply` 会**覆盖**下一镜已有的自定义首帧 → 默认只预览；已有自定义首帧的镜头默认跳过，要覆盖加 `--force`
- `run --chain` 只用于定稿（`--stage final`），不能和 `--takes` / `--stage draft` 同时用
- 这些操作会改分镜，属于必须先问用户的动作（见最后一节）
- Veo 3.1 有已知限制：首帧与参考图不能同时用于同一次生成，二选一

如果衔接怎么调都别扭，插一个短促的**缓冲镜头**（手部动作、环境细节、光影扫过）通常比反复重生成更省。

## 阶段详解

### 阶段 2 · 镜头表六要素

一行一镜，写清六件事：**景别、主体动作、环境、光线、镜头运动、时长**。
分镜阶段就把转场方式标出来，能省掉大量后期补救。

| 经验值 | 建议 |
|---|---|
| 单镜时长 | 3–8 秒；5 秒最通用（模型只支持 4/5/6/8/10） |
| 15 秒成片 | 6–10 镜 |
| 60 秒成片 | 20–35 镜 |
| 重试预算 | 每镜按 2–4 次估算力与时间 |
| 单镜内容 | 一个动作、一个机位；「先走近再转身再抬头」一定会糊 |

**prompt 三段式**（把 prompt 当生产文档，不当随口描述）：

```
[固定前缀] 身份块 + 统一风格 + 光线（逐字不变）
[变化主体] 这一镜的动作、景别、构图、运镜
[固定后缀] 质感 + 排除项（negative 字段）
```

抽象词全部换成可拍的物理描述：「高级感」→「低饱和、大面积留白」；
「有情绪」→「缓慢推进、逆光、暖调」；「有冲击」→「低角度仰拍、高对比」。
别写否定（「不要有人」会被理解成「有人」），排除项写进 `negative`。

### 阶段 3 · 静帧预演（最省钱的修改窗口）

用 ImageGen 给每镜出静帧，存 `images/`，分镜里填 `"image": "images/s1.png"`。
**静帧阶段改构图只要几秒，视频阶段改要几分钟 + 真钱。**

筛选标准不是「好不好看」，是「能不能承接下一镜」：
角色是否与参考一致、构图有没有为运动留空间、光线方向是否与前后镜连贯、有没有结构错误。
淘汰率 50% 以上很正常。人物类内容建议先做**角色设定表**（正面/侧面/半身/全身），
每个镜头都基于同一批参考图生成。

⚠️ 生成静帧会调用生图模型、可能额外计费，**先问用户要不要做**。

### 阶段 4 · 草稿 animatic

```bash
vs.py run --stage draft     # 720p 低成本，片段命名 draft-sX-*，不写回分镜
vs.py animatic              # 拼成 .vs/work/animatic.mp4 看节奏
```

粗剪放在 `.vs/work/`，**绝不写进 `output/`** —— 用户答「只要片段」时交付目录必须保持干净。
草稿是内部预演，**不作为交付物**。看的时候重点问：有没有重复信息的镜头、
结尾是不是来得太早、某个蒙太奇是不是太薄。这些问题在静帧/草稿阶段改几乎不花钱，
在定稿之后改就要整段重跑。

定稿时提示词不变，只换质量：`vs.py run --stage final`。

### 阶段 5 · 候选版本

```bash
vs.py run --takes 3          # 每镜 A/B/C，seed 依次 +1（模型支持时）
vs.py takes                  # 列出所有候选及 seed / 模型 / prompt
vs.py pick s1 B              # 只改分镜引用，不重新生成、不额外花钱
```

版本**永不覆盖**，重复跑会追加 D/E/F。选版时把同一镜的候选并排看：
脸部是否一致、动作是否符合预期、光线是否连贯。
每镜的 `prompt / seed / model / 参考图 / 版本` 都存在 `.vs/jobs.json` 的 `extra` 里，可复现。

⚠️ `--takes 3` 会让生成成本大约翻三倍，**必须先报账并得到用户确认**。

### 阶段 6 · 质检

```bash
vs.py qc
```

自动查：片段是否存在、字幕是否超长、**是否混用了多个模型/版本**、参考图与尾帧链文件是否齐全、
身份块是否填写、总时长与镜头数是否匹配。
再输出 7 条机器替不了的人工清单（首尾帧并排、光源方向、人脸占比、头尾形变、动作连贯、统一调色、通片节奏）。

**关键纪律**：每生成完一镜就立刻检查首尾帧，发现漂移**当场重跑那一镜**
（`run --only sX --force`），别让漂移累积到后面的镜头。
全景里人脸小于画面约 20% 时模型容易换成通用脸 → 身份关键的中近景别用广角。

### 阶段 7 · 后期

统一调色 / 一套 LUT 是掩盖不同模型色温差最便宜的手段；
剪辑点藏在动作里（转身、开门、物体掠过）；头尾各留一点 handles 裁掉不稳定帧；
环境底噪（房间混响、街道声）比提高分辨率更能让画面显得真实。

**但用户没授权就一项都别做** —— 见 `intake.md` 与 SKILL.md 的铁律。
`assemble` 默认就是纯拼接。

## 常见失败模式速查

| 症状 | 最可能的原因 | 修法 |
|---|---|---|
| 每段像换了个人 / 换了套衣服 | 没有共享视觉锚点 | 锁一张主参考图 + 身份块逐字复用 |
| 参考图一样，但帽子/包颜色变了 | 细节只写在部分 prompt | 写进身份块，所有镜头一致 |
| 切口处「气质」变了 | 没做末帧接首帧 | `chain --apply` 后重生成后续镜头 |
| 隔天再跑风格变了 | 模型版本/会话默认值变了 | 看 `.vs/model-lock.json`，别换模型 |
| 广角里脸崩 | 人脸占比 < 20% | 改中近景，广角只用来交代环境 |
| 长镜头里人变形 | 单次生成太长，内部拼接丢线索 | 拆成 5 秒多镜，靠剪辑串 |
| 动作夸张、肢体断裂 | 一镜塞了太多动作 | 一镜一动作，prompt 加「缓慢」「轻微」 |
| 画面里出现怪字 | 模型不会写字 | 文字一律后期字幕加，`negative` 加「文字, 字幕, 水印」 |
| 口型对不上 | 先生成脸再后期配音 | 用原生音频模型（Veo 3.1 / Seedance）一次生成 |

## 成本与迭代纪律

- 改东西一次只改一个变量。同时改 prompt + seed + 模型，出了好结果也不知道是哪个起效。
- 先 `estimate` 报账，且**按实际生成量带倍数**：`estimate --takes 3 --draft`（= ×3.5）。
  确认单也要用 `plan --takes 3 --draft --chain`，别让用户按 1 倍的价格点头 3.5 倍的生成。
- 静帧 > 草稿 > 定稿，越靠前越便宜；把创意决策放在便宜的阶段。
- 只重跑坏的那镜（`--only`），别全量 `--force`。
- 一个项目一个模型家族，别为了某镜「更好看」临时换，风格断裂的代价更大。

## 什么时候可以简化

| 内容类型 | 可以跳过 |
|---|---|
| 纯风景 / 抽象 / 转场素材，无 recurring 主体 | 制作圣经、尾帧链、多候选 |
| 只要一个片段（SKILL.md 场景 B） | 除 `gen` 外全部 |
| 用户明确说「只要片段、我自己后期」 | 所有后期与 animatic（animatic 属内部预演也要先说） |
| 3 镜以内、无人物 | 草稿预演可省，静帧仍建议做 |

**不能省**：成本确认、模型锁定、可复现记录（这三项不花钱，省了一定后悔）。

## ⚠️ 新增环节同样要先问用户

本管线增加了几件会**多花钱 / 改分镜**的事，它们不是默认动作，必须单独获得同意：

| 动作 | 为什么要问 |
|---|---|
| 生成静帧 / 角色设定表 | 额外调用生图模型，可能另计费 |
| `run --stage draft` | 多一整轮生成，成本增加 |
| `run --takes 3` | 生成量 ×3 |
| `run --chain` | 会改写下一镜首帧图、改 `storyboard.json`，需 ffmpeg |
| `chain --apply` | 补救用；会覆盖下一镜首帧图，且**必须重跑后续镜头**才生效 |
| `animatic` | 需要 ffmpeg，且属于额外加工 |
| `--use-refs` / `--unlock-model` | 改变生成方式，可能破坏一致性 |

**用户没答 = 不做。** 默认路径仍然是：问清楚 → 建项目 → 写分镜 → `run`（一次、定稿、单模型）
→ 按用户第 3 轮的答案决定 `clips` 还是 `assemble`。
